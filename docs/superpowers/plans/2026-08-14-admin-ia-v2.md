# Admin IA v2 (P1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the device-switcher admin with the fleet-first shell — Fleet Home plus a per-clock Control Room (Playlist / Apps / Settings tabs) — built to the Figma wireframes, with the dev-safety push guard and honest `pushOutcome` reporting.

**Architecture:** URL-scoped device context (`/admin/clock/:deviceId`, no global device state), seven surfaces rebuilt to board fidelity on the existing TanStack Query + zod-schema-form stack, one server touch (`pushOutcome` + dev push guard). Foundation lands first (routes, shell, stubs, shared art/chip components) so six surface builders can fan out into worktrees without ever editing a shared file.

**Tech Stack:** React 19 + react-router 7 (`BrowserRouter basename="/admin"`), TanStack Query 5, zod 4 schema-forms (`SchemaForm` + PR #49 array widgets), dnd-kit, Tailwind v4 under `.admin-root`, Express 5.

**Spec:** `docs/superpowers/specs/2026-08-08-admin-ia-v2-design.md` — read it first; this plan argues from it.

## Global Constraints

- **Scope fences (spec):** no `fleet.json`/device-config schema changes; no kiosk behavior changes; no new API endpoints; no live previews, schedule UI, activity feeds, identify button, mashup/mirror, maintenance rows.
- **P1 reality — device state is a stub.** `GET /api/device/state` returns `currentScreenId: null` until P2 telemetry, and there is no admin-side proxy for other devices' state (and "no new endpoints" forbids adding one). Therefore P1 renders from **config + health only**: card art falls back to the first playlist instance, the "now: X" line becomes a rotation summary ("N screens · 30s"), and the playlist "now" badge is omitted — never faked. The `['device', id, 'state']` query key arrives in P2.
- **Tokens:** admin semantic tokens only, via the arbitrary-value idiom (`text-[hsl(var(--success))]`); `npm run check:tokens` must stay green. Do not introduce a second idiom (open decision in CLAUDE.md). Border-color utilities are currently dead (unlayered reset) — do not fight it; a parallel session owns that fix.
- **Unslop bindings apply to every surface** (`.claude/skills/unslop/SKILL.md` Phase 0/1): verb+object copy, no fabricated device data, offline/empty/error states designed, 375px pass, lucide icons only.
- **Testing floor (spec):** Vitest for the legacy-route redirect map, `useDeviceId` resolution, Add-Screen creation defaults + navigation target, push-guard outcomes (prod / dev-self / dev-remote / override). Keep tests pure-function against extracted logic — this repo's vitest runs in node env, no DOM library, and that stays true.
- **Definition of done per task:** `npm run lint && npm run check:tokens && npm test` green (surface builders); `./scripts/gates.sh` green (integration); commit per task.
- **Wireframes are the fidelity source:** Figma file `JAjMCsw8hXx38locrxP5gd`, page "Admin Panel" `73:962` — phone wireframes section `81:701` (frames `wf/1-fleet-home` … `wf/10-face-gallery`), desktop keys `89:720`. Captured PNGs land in the scratchpad at execution time; each surface task names its frame.

## Execution protocol (option 7 — gated fan-out)

1. **Batch A (foundation)** runs first: Task 1 (server, delegatable) in parallel with Task 2 (client shell — the shared-files task, done by the orchestrator, never a fan-out agent).
2. **Batch B (surfaces, Tasks 3–8)** fans out one agent per task, `isolation: worktree`, branched from the post-Batch-A commit. A surface agent owns ONLY its listed files. **Composition gaps get reported, never forked:** if a shared piece (shell, art resolver, chip, ui primitive) doesn't fit, the agent notes the gap in its report and works around it locally without editing the shared file.
3. Each surface agent's prompt carries: its task section verbatim, the spec's matching surface paragraph, its wireframe PNG path, the unslop Phase 0/1 bindings, and the standing rules (semantic tokens only, no fabricated data, no new deps).
4. **Batch C (integration, Tasks 9–10)** is orchestrator-only: reconcile real imports, delete the old world, unslop Phase 2 audit, `gates.sh`, browser + on-glass verification, ship.

- [ ] **Step 3: implement** in `server/device-push.ts` — pure function + wire-in:

```ts
export type { PushOutcome } from '../src/shared/types';

// Dev trap this closes: `npm run dev` on the Mac mounts the real admin
// routes, so editing any device ≠ self pushed config to REAL clocks.
export function classifyPush(
  target: DeviceId,
  own: DeviceId,
  nodeEnv: string | undefined,
  allowRemote: boolean,
): 'push' | 'suppress' {
  if (nodeEnv === 'production') return 'push';
  if (target === own) return 'push';
  return allowRemote ? 'push' : 'suppress';
}
```

In `pushToDevice`, before the host lookup: `const verdict = classifyPush(deviceId, ownId, process.env.NODE_ENV, process.env.ADMIN_ALLOW_REMOTE_WRITES === '1'); if (verdict === 'suppress') return { ok: true, outcome: 'dev-suppressed' };` — do NOT mark the device pending (a suppressed push must not enter the retry drain). Existing return sites become `{ ok: true, outcome: 'applied' }` / `{ ok: false, outcome: 'queued', reason }`. In `src/shared/types.ts` add `export type PushOutcome = 'applied' | 'queued' | 'dev-suppressed';`.
- [ ] **Step 4: thread through admin-routes.ts** — each write handler already calls `pushToDevice`; capture its result and put `pushOutcome: result.outcome` in the JSON per the Produces block (DELETE switches `res.status(204).end()` → `res.json({ pushOutcome })`).
- [ ] **Step 5: run** `npx vitest run server/ && npm run lint` — PASS; **commit** `feat(server): pushOutcome + dev-safety push guard`.
